## Custom Project

### Dataset

The dataset used by the Kafka producer is `sales.csv`.

The dataset contains sales transaction records generated for a fictional online learning business.
Each record represents a customer purchase and includes information about the order,
 customer, product, region, and payment details.

Fields included in each record:

- order_id
- datetime
- region_id
- currency_code
- product_id
- unit_price
- quantity
- is_online
- customer_id
- payment_method
- discount_code
- device_type
- referral_source
- customer_note
- is_new_customer

I used the original sales dataset provided in the project and processed it through Kafka before
storing and analyzing the results.

### Kafka Messages

The producer sends sales transaction records as Kafka messages.

- Producer: `kafka_producer_case.py`
- Kafka Topic: `streaming-05-storage-case`
- Message Key: `region_id`
- Message Value: sales transaction record in JSON format

The messages were validated before being sent to Kafka.
 Each message represented one sales transaction and was delivered to the Kafka topic for downstream
 processing.

### Consumer Processing

The consumer receives sales messages from Kafka and processes them one at a time.

The custom consumer file is:

`kafka_consumer_sabri.py`

The consumer:

- Reads messages from Kafka
- Validates required fields
- Calculates derived values:

  - subtotal
  - tax
  - total
- Stores valid records in:

  - `consumed_sales.csv`
  - `sales.duckdb`
- Logs processing information and summary statistics
- Tracks total sales, average sales, minimum sale, maximum sale, and highest order total

For this project run, the consumer processed 50 sales messages successfully.

### Experiments

#### Phase 4 Modification

I created a custom consumer named `kafka_consumer_sabri.py`.

I added a new summary metric called **Highest Order Total** to display the largest
order processed during execution. This provided additional visibility into
sales performance and improved the final summary statistics.

### Results

The producer successfully generated and sent 50 sales messages.

The consumer successfully consumed, validated, enriched, and stored all records.

The analytics dashboard generated the following results:

- Total Revenue: $3835.10
- Total Orders: 50
- Average Order Value: $76.70
- Highest Order Total: $323.95

The project also produced visual reports and a summary CSV file for further analysis.

### Interpretation

This project demonstrated the complete Kafka streaming workflow from data production to storage and
business analytics.

Compared to the original example, I extended the project by adding a custom consumer metric and
creating a separate analytics dashboard for post-storage analysis.

Watching messages move through Kafka helped me better understand how
 streaming systems process data in
real time and how information can be persisted for future reporting.

The consumed messages provided insights into sales performance, regional activity, and product revenue
trends.

The business intelligence generated from the stream showed how organizations can transform raw

streaming events into meaningful reports, metrics, and visualizations that support decision-making.
